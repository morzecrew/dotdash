# dotdash

A [morzer](https://github.com/morzecrew/morzer) bundle that runs an Xray gateway
on a single Docker host: REALITY on port 443 in front of a website served by
Caddy, an optional DNS-based entry point, and all outbound traffic routed
through an upstream proxy you provide.

## Channels

| Tag | |
| --- | --- |
| `ghcr.io/morzecrew/dotdash:main` | every push to `main`, signed with the dev key; may be broken |
| `ghcr.io/morzecrew/dotdash:stable` | releases: a `vX.Y.Z` tag on `main`, signed with the release key |
| `ghcr.io/morzecrew/dotdash:X.Y.Z` | one exact release |

## Install

Requires a domain whose DNS you can edit (any provider), a Linux host with
Docker ≥ 28 and Compose ≥ 2.35, `sops`, `age`, morzer ≥ 0.12.0, and upstream
proxy credentials. `example.com` below is your domain.

**1. DNS**: `example.com  A  <server IP>`.

**2. Server**: open 80/tcp and 443/tcp (80 is for the certificate). Docker's
published ports bypass ufw and firewalld, so the host firewall guards only the
rest, SSH included: allow keys only (`PasswordAuthentication no`).

**3. Deploy**

```sh
morzer secret recipients generate-recovery-key ~/dotdash-recovery.key   # store off the machine
sudo morzer init --release oci://ghcr.io/morzecrew/dotdash:stable \
  --require-signature --signing-key "$MINISIGN_RELEASE_PUBKEY" \
  --domain example.com --recovery-recipient age1… \
  --set upstream_host=proxy.provider.example --set upstream_port=1080
# also --set upstream_protocol=http, --set upstream_tls=true if the proxy needs them

sudo morzer secret set upstream_username
sudo morzer secret set upstream_password
sudo morzer apply
```

`MINISIGN_RELEASE_PUBKEY` is this repository's variable of that name
(`gh variable get MINISIGN_RELEASE_PUBKEY -R morzecrew/dotdash`). If the package
is private, log root's Docker in to ghcr first.

Keys, ids and paths are generated by morzer, and Caddy gets a Let's Encrypt
certificate on first start. `apply` succeeds only once Xray has fetched a URL
through the upstream proxy and port 443 serves the site with a trusted
certificate.

**4. Clients**

```sh
morzer task run client-config --output             # every client
morzer task run client-config --output -- phone    # one
```

Prints a REALITY link (v2rayN, v2rayNG, Hiddify, Happ, Streisand), an XHTTP
link, and an Xray outbound for the DNS tunnel when it is on. Treat the output
as a password.

Each device should get its own id. `morzer secret edit vless_clients` opens the
list, one `<uuid> [name]` per line (`uuidgen` makes an id). Add a line for a
device and delete it to revoke the device; Xray restarts on save. A revoked
device still knows the shared keys. If it must not even recognise the server,
also rotate `reality_key` and `vless_seed` (`morzer secret rotate <name>`) and
resend every device's links.

### DNS tunnel (optional)

Delegate `t.example.com` to the server, open 53/udp, and add `--profile xdns`
to `morzer init` in step 3. For another zone, add `--set xdns_domain=<zone>`. If
`systemd-resolved` holds port 53, set `xdns_bind` to the public IP.

```text
ns.example.com.  A   <server IP>
t.example.com.   NS  ns.example.com.
```

A zone under a domain of its own is better, such as `--set
xdns_domain=t.example.net` delegated from `example.net`: a resolver that flags
tunnel queries flags the domain they are under, and blocking it would take
`example.com` with it.

### CDN (optional)

The XHTTP link also works through a CDN that proxies HTTP/2 to
`https://example.com`: put the CDN's name in the link's address. If the CDN
proxies `example.com` itself, use the server IP in the REALITY link. Check the
CDN's terms first; some, Cloudflare's self-serve plans among them, prohibit
proxy services.

## Keeping it running

**Updates.** To install each release from `:stable` unattended, nightly at
03:30 unless `update.schedule` says otherwise:

```sh
sudo morzer config set update.check=true
sudo morzer config set update.channel=oci://ghcr.io/morzecrew/dotdash:stable
sudo morzer config set update.auto_apply=true
```

This hands whoever holds the release key root on the machine, since hooks run
as root; the install above already requires that key's signature. A release
that fails to install is not retried, and `morzer status` says so. See morzer's
[unattended updates](https://github.com/morzecrew/morzer/blob/main/pages/docs/operating/unattended-updates.md).

**Backups.** morzer backs up every night: the secrets, encrypted to the
recovery key, and Caddy's certificates. They stay on the machine until it has a
target; `file://` and `ssh://` work too. See morzer's
[backups](https://github.com/morzecrew/morzer/blob/main/pages/docs/operating/backups.md)
and [recovering a lost machine](https://github.com/morzecrew/morzer/blob/main/pages/docs/operating/recovering-a-lost-machine.md).

```sh
sudo morzer backup target add s3://bucket/dotdash --credentials backup_s3
```

**Alerts.** A target receives morzer's event JSON: each failed apply, update or
backup, each staged release, and every morning what `doctor` found wrong. See
morzer's [notifications](https://github.com/morzecrew/morzer/blob/main/pages/docs/operating/notifications.md).

```sh
sudo morzer notify target add https://hooks.example/morzer --min-level warn
```

## Parameters

| Name | Default | |
| --- | --- | --- |
| `upstream_protocol` | `socks` | `socks` or `http` |
| `upstream_host`, `upstream_port` | required | upstream proxy |
| `upstream_tls` | `false` | connect to the upstream over TLS |
| `upstream_udp` | `false` | relay UDP via a SOCKS5 upstream with UDP ASSOCIATE; otherwise UDP is dropped |
| `https_port` | `443` | host port for REALITY and the site |
| `xdns_domain` | `t` | delegated tunnel zone (`xdns` profile); a name with no dot is under the domain |
| `xdns_bind` | `0.0.0.0` | host address for UDP/53 |
| `xdns_mtu` | `900` | tunnel reply size; lower if replies get lost |
| `log_level` | `warning` | Xray error log; access log is always off |
| `healthcheck_url` | `https://www.gstatic.com/generate_204` | fetched through the upstream by the healthcheck |
| `cert_issuer` | `acme` | `acme` (Let's Encrypt) or `internal` (Caddy's own CA, for a machine the internet cannot reach) |

Check a change with `morzer release verify ./bundle --render-check`.

## CI

[bundle-ci](https://github.com/morzecrew/bundle-ci) builds, signs and
smoke-tests the bundle on every pull request and push. A push to `main`
publishes `:main`, and a tag `vX.Y.Z` on `main` publishes `:X.Y.Z` and
`:stable`. The smoke install (`.github/smoke.d`) runs a stand-in upstream
proxy and `cert_issuer=internal`, then connects clients over REALITY and XHTTP.
